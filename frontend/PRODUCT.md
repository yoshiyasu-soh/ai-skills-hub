# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

社内の全社員(Claude Code / Cowork 等のAIツールを利用する社員)が対象。特定の部署・職種への絞り込みはなく、スキル・プロンプトを「投稿する側」「探して使う側」の両方を兼ねる。ゲストアカウントは利用不可(Cloudflare Access + Entra ID SSO によりメンバーアカウントのみ許可)。

## Product Purpose

Claude Code のスキル・プロンプトを社内で共有するためのサイト。個々人が作った再利用可能なAI活用ノウハウ(SKILL.md/ZIP、プロンプトのテキスト)を投稿・検索・利用できるようにし、車輪の再発明を防ぎ、社内のAI活用レベルを底上げすることが成功の指標。

## Positioning

単なるファイル置き場や社内Wikiとの違いは、社内の知見を「可視化・評価」できる点。DL数・コピー数・お気に入り数によるランキング、投稿者プロフィール(Entra ID連携による役職・部署等の自動同期)により、何が実際に使われていて信頼できる知見かが一目でわかる。加えて `/api/mcp` によるMCPサーバー公開でClaude Code / Cowork等から直接検索・参照でき、プロンプトはclaude.aiへワンクリック遷移できるなど、AIツールの実作業導線に直接組み込まれている点も他の汎用ドキュメント共有手段にはない価値。

## Operating Context

社員がClaude CodeやCowork、claude.ai等でAI作業をする中で、既存のスキル/プロンプトを探して使う、または自作したものを共有する場面で使われる。認証はCloudflare Access経由のEntra ID(Azure AD) SSOに委譲。プロンプトはワンクリックでクリップボードにコピー、または本文入力済みの状態でclaude.aiの新規チャットに遷移可能。スキルはブラウザから直接ダウンロード。

## Capabilities and Constraints

- スキル投稿(ZIPまたはSKILL.md単体)/プロンプト投稿(テキスト)。SKILL.md選択時はフロントマター(name/description)と本文からタイトル等を自動入力。
- 投稿の編集・削除は投稿者本人のみ。
- タグ機能: デフォルトタグ+投稿者による新規タグ追加、複数タグ絞り込み(AND条件)。
- タイトル・説明文の部分一致検索。
- ソート: 新着順/更新順/利用数順(DL数・コピー数)/お気に入り数順/名前順。
- お気に入り登録・お気に入り一覧。
- DL数(スキル)/コピー数(プロンプト)の記録とランキング表示(累計・過去7日・過去30日)。
- ユーザープロフィール(表示名・姓名・役職・会社名・部署・従業員の種類)は誰でも閲覧可能。Microsoft Graph連携時はEntra ID情報を自動同期、未連携時はメールのユーザー名部分にフォールバック。
- MCPサーバー(`/api/mcp`): 現状は参照系(検索・取得)のみ、投稿・編集はMCP経由では不可。
- 認証・認可はすべてCloudflare Access側のポリシーに委譲。Worker自身はログイン画面やトークン発行ロジックを持たない。ゲストアカウントは拒否。
- インフラ: Cloudflare Workers(Hono) + D1(メタデータ) + R2(スキルZIP)。
- 未実装・スコープ外(今後の拡張候補): `npx skills add`のようなCLI配布、他ツールへのワンクリック連携、コメント・レビュー機能、投稿の承認フロー/モデレーション。

## Brand Commitments

プロダクト名は「AI Skills Hub」(index.html の title、LogoMark コンポーネントで確定済み)。名称・表記の変更が必要な場合はユーザーに確認する。

## Evidence on Hand

実データ・利用実績の具体数値・導入事例などは未提供。今後の作業でこれらを捏造しないこと。

## Product Principles

1. 投稿のハードルを下げる — SKILL.mdのフロントマター自動読み込みなど、投稿作業を最小限にする。
2. 利用実績に基づく信頼性の可視化 — DL数・コピー数・お気に入り数・投稿者プロフィールで「使われている/信頼できる」知見かを判断しやすくする。
3. AIツールへの直接接続を優先する — コピーやダウンロードで終わらせず、claude.aiへの遷移やMCP経由の参照など、実際の作業導線に組み込む。
4. 認証・認可はCloudflare Access/Entra IDに一元化し、Worker側で独自のログイン機構を持たない。
5. 投稿者本人以外による編集・削除を許可しない(誤って他者の知見を壊さない)。
